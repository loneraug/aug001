■ 수정 배경
녹화 목록(곡 2개 이상)에서 모든 곡이 전역 재생 속도(TS.speed)로만 녹화되었다. 실제 재생처럼 녹화에서도 곡마다 속도를 정할 수 있게 하고,
속도가 달라진 곡은 목록의 재생시간에 반영하고 글씨색(전역보다 빠르면 빨강, 느리면 파랑)으로 알 수 있게 한다.

■ 요약
1. 곡 항목에 spd(곡별 재생 속도, 기본 null) 추가. null 이면 전역 재생 속도를 따라가고(전역을 바꾸면 같이 바뀜), 값이 있으면 그 곡만 그 값(전역 대비 비율이 아니라 전역과 같은 절대 배속).
2. 목록의 곡 행을 우클릭하면 "재생 속도..." 메뉴 -> 숫자 입력 창(현재 전역 속도 표시, 0.25~4배, 소수 둘째 자리, 검증은 trSetSpeed 재사용). 칸을 비우고 확인하면 미지정(전역 따라감)으로 복귀.

4. 행 오른쪽 시간, 총 길이, 예상 용량이 곡별 실제 속도 기준으로 계산됨. 곡별 실제 속도가 현재 전역 속도보다 빠르면 시간 글씨 빨강, 느리면 파랑(같거나 미지정은 기본색, 라이트/다크 각각 색 지정). 전역 속도를 바꾸면 시간/색도 다시 계산. 배율 글자는 붙이지 않고 결과 txt 에도 적지 않음.
5. 순차 경로와 병렬(Worker) 경로 모두 곡마다 실제 속도로 녹화. 대기/시작 프레임/프레임 수는 곡별 길이 기준. 모든 곡이 미지정이면 이 수정 전과 완전히 같은 출력.
6. __recLast 에 곡별 실제 속도 배열 speeds 한 필드만 추가. 빈 목록 단일 녹화는 변화 없음(전역 속도).

목록 녹화(곡 2개 이상)를 곡마다 순서대로 처리하면 시간이 오래 걸린다. 곡 하나당 Web Worker 하나가 그 곡의 소리 합성, 화면 그리기, H.264 인코딩을 맡고 동시에 최대 "병렬 스레드" 개를 돌려 처리 시간을 줄인다. 모든 곡이 끝나면 병합한다.

■ 요약
1. 버전 표기: title, h1 두 곳만 v0.25 (h1 끝에 "목록 녹화 병렬 처리").
2. 녹화 설정 줄(정밀 용량 옆)에 "병렬 처리" 체크박스(#recpar)와 "병렬 스레드" 숫자칸(#recthr, 기본 6) 추가.
3. 스레드 값은 정수로 읽어 1 미만/빈칸/숫자 아님이면 1(상한 없음). 정밀 용량(#recprec)과 병렬 처리는 한쪽을 체크하면 다른 쪽이 해제된다.
4. 목록이 1곡 이하에서 2곡 이상이 되는 순간 딱 한 번만 병렬 체크 + 정밀 해제. 이후 사용자의 선택은 덮어쓰지 않고, 곡 수가 줄어도 체크는 그대로.
5. 병렬 경로(recStartPar) 사용 조건: 목록 녹화 + #recpar 체크 + T>=2 + 재생 가능한 곡 2개 이상. 그 외(T=1 포함)는 v0.24 순차 경로 그대로. 빈 목록 단일 녹화는 변화 없음.
6. Worker: 곡 PCM(볼륨 곱 적용)과 끝 무음(trail) 계산 -> 대기 프레임 확정 -> 곡의 Nsong+Nwait 프레임을 OffscreenCanvas 로 그려 VideoEncoder(H.264)로 인코딩 -> 청크+avcC 반환. 곡 첫 프레임은 키프레임, GOP 는 곡 안 프레임 번호 기준.
7. 메인: 곡 순서대로 PCM 을 인코더 1개에 이어 넣고(대기 무음 포함, v0.24 recAudioList 와 같은 누적 샘플 규칙), 곡 조각을 이어 붙여 recBuildMp4 로 MP4 생성. 시작 프레임은 곡별 (Nsong+Nwait) 누적.
8. 안전장치: 곡 조각 avcC(SPS/PPS)가 다르거나, Worker/OffscreenCanvas/Worker 안 VideoEncoder 를 못 쓰거나, Worker 오류/프레임 수 불일치가 나면 병렬 결과를 버리고 순차 경로로 자동 전환(로그에 사유).
9. 진행률은 곡별 합성+그리기 진행 평균, [녹화 중단]은 모든 Worker terminate + 결과 파일 없음. 결과 표시/txt 는 v0.24 와 같고 __recLast 에 par:true, threads 추가.
10. 외부 SF2 는 Worker 가 원본 바이트로 다시 읽어야 하므로 sfParseExternal 의 info 에 raw(원본 버퍼) 한 필드만 추가.

■ 미검증
- 실제 다코어 속도 이득(이 환경은 코어 1개: 순차 6.6초 대 병렬 8.1초로 오히려 느림, 8곡 480p), 실제 긴 녹화, 실제 스피커 소리, 플레이어 호환성, 대용량 메모리(곡별 PCM/조각을 모두 메모리에 보관), 외부 SF2 사용 병렬 녹화(Worker 마다 복사본 -> 메모리 = 크기 x 동시 수), 사용자 눈으로 본 UI.
